### 实际呈现的架构

```text
CLI / FastAPI
  → LangGraph ReAct Agent + 通义千问模型
  → MultiServerMCPClient
  → 天气 / 文件工具 / 高德远程 MCP
```

这是“一个 Agent + 多个工具/服务”的示例。多个 MCP 服务器不是多个 Agent。多角色协作、路线约束求解、订单、交易及运营闭环需另行设计。

### 可借鉴与需要校正的部分

| 文档内容 | 本项目可如何参考 | 使用前需要核对 |
|---|---|---|
| 工具清单与服务器配置 | 显式管理工具、参数和服务位置 | 当前适配器/API 版本、工具契约、失败表示和资源清理 |
| FastAPI lifespan | 服务启动/关闭管理连接与 Agent | 多 worker、重启及异常退出时是否按预期清理 |
| `ainvoke` | 异步等待模型和工具 | 异步语法不自动保证调用链没有阻塞 |
| `thread_id` | 区分会话上下文 | 会话隔离与授权不是同一机制，不能直接信任客户端传入 ID |
| `InMemorySaver` | 演示单进程内的会话状态 | 进程重启不保留；它不是磁盘持久化或完整业务任务恢复 |
| `create_react_agent` | 参考工具调用循环 | 先核对选定版本是否仍推荐该入口，不照旧文章无条件安装最新依赖 |
| STDIO / SSE | 理解本地子进程和远程传输 | “只支持两种方式”是文档口径；当前官方 SDK 还列出 Streamable HTTP，按服务及版本选择 |
| “用了 MCP，所以不是 RAG” | 区分工具协议与检索增强 | 两者可组合，不能当作互斥技术路线 |

文章里的示例远程地址不直接作为本项目依赖。文件写入和表达式执行不是行程应用首版的必要能力，不复制通用可执行代码工具。
