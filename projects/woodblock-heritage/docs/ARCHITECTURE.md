# 整体架构（木版年画 / woodblock-heritage）

> **状态基线**：已提交 `00c5502`（2026-11-11）。第 1–7 节是**当前已实现**的审核/发布切片；第 8 节是**目标态**（受控动态 DAG），尚未实现，不得当作现状引用。
> 历史年画工程的本体/抽取/Neo4j 是既有资产，不在本仓库实现范围内。

## 1. 分层总览（当前）

                │                              │

**依赖方向**：接口层 → 服务层 → 契约/存储；`service.py` 不直接处理 HTTP，`store.py` 不做业务判断。图片解码独立成模块，便于限额与错误分类。

## 2. 请求生命周期（当前）

1. `POST /sources`：校验 media_type/许可 → base64 严格解码 → Pillow `verify` + 重新 `load` → SHA256 → 同哈希来源：元数据一致返回 200，不一致 409；否则存 BLOB + 元数据 201。
2. `POST /works`（幂等键）：校验 schema/来源 → 区域坐标按实际宽高归一化 → 断言强制重置为 `insufficient/unreviewed` 并重算结构 → 未知谓词/缺证据保留 invalid + blocking issue → 保存不可变 v1（含 `raw_import`）201。
3. `POST /works/{id}/reviews`（幂等键）：先查幂等 → 比较 `expected_version` → 逐条 approve/reject/revise → 问题处置 → 同一事务写事件、v+1、当前指针、幂等响应。
4. `POST /publications`（幂等键）：校验当前版本 → 门禁 → 同版本快照复用或新建不可变快照。
5. `GET /knowledge`：只返回 `publication.version == works.current_version` 的快照。

## 3. 模块职责

| 模块 | 职责 | 明确不做什么 |
|---|---|---|
| `app/models.py` | Pydantic 请求契约、冻结谓词、字段长度 | 不写库、不做业务裁决 |
| `app/images.py` | base64 严格解码、PNG/JPEG 完整解码、体积/像素限额 | 不做 OCR/VLM |
| `app/store.py` | 表结构、WAL、事务、幂等读写、版本读取 | 不做业务判断 |
| `app/service.py` | 三状态轴、结构校验、审核裁决、发布门禁、快照 | 不做 HTTP、不解码图片 |
| `app/main.py` | 路由、统一错误体、CSP、Origin 检查、静态页托管 | 不写业务规则 |
| `web/` | 同源页面、canvas 区域覆盖、审核交互 | 不内联脚本、不计算业务结论 |
| `scripts/` | `demo_e2e.py` 真实 HTTP 冒烟、`ui_full_e2e_cdp.py` CDP 流程、gold 校验 | 不替代 pytest |

## 4. 数据模型

| 对象 | 关键字段 | 作用 |
|---|---|---|
| source | `content_hash` UNIQUE、media_type、width/height、BLOB、许可策略、metadata | 去重、追溯、发布许可门禁 |
| region | 页码、bbox、归一化坐标、原文 | 把断言定位到图上 |
| claim | 谓词、值、`evidence_refs`、三状态轴 | 一条可审核的候选知识 |
| work / version | `(work_id, version)`、完整 payload、当前指针 | 不可变版本、历史回看 |
| review_event | 操作、from/to、reviewer、reason、decisions | 审核追溯 |
| publication | 作品版本、快照 claims、许可 | 发布与历史 |

**三状态轴**

| 轴 | 回答的问题 | 谁能改 |
|---|---|---|
| validation | 结构是否合约：谓词在白名单、区域存在、值非空 | 服务重算 |
| support | 来源是否支持这句话 | 人工批准时显式给 `supported` |
| review | 人是否已裁决 | 人工 approve/reject |

`valid + insufficient + unreviewed` 是正常候选态；**有引用不等于支持，支持不等于批准**。

## 5. 审核事务

```text
POST /works/{id}/reviews (Idempotency-Key, expected_version, decisions)
  → 查幂等：同键同哈希 → 返回原响应；同键异哈希 → 409
  → BEGIN IMMEDIATE（先拿写锁）
      ├─ 读当前版本；expected_version 不一致 → 409 VERSION_CONFLICT
      ├─ 逐条应用 approve/reject/revise；revise 回 unreviewed/insufficient
      ├─ 问题处置（resolved/rejected）
      ├─ 写 review_event
      ├─ 写新 work_version（不可变）
      ├─ 移动 works.current_version
      └─ 写幂等响应
  → COMMIT
```

并发：两个独立连接同时提交同一 `expected_version`，只有一个成功；另一个 409，不会产生两个版本或两个事件。版本检查必须在写事务内，事务外“先读后写”会竞态。

## 6. 发布门禁

1. 幂等重放 → 2. 作品与当前版本 → 3. 所有来源许可允许发布 → 4. 无 unreviewed 断言、无 open blocking issue → 5. 至少一条合格断言 → 6. 按 `(work_id, version)` 唯一创建/复用快照。

合格断言 = `approved + supported + valid + 值非空 + 证据非空`。

- 坏断言被 reject 后，其关联结构 issue 不再阻断好断言；不关联的全局问题仍阻断。
- 许可只有 `synthetic-only`、`local-unverified-no-publication`、`cleared-for-publication`；第二种名字像“本地”，实际**禁止发布**。
- 许可未核时，即使断言全批准也 409，不生成空快照。许可是本地自述声明，不验证权利人文件。

## 7. 安全与限制（当前）

- CSP：`default-src 'none'`，脚本/样式仅同源，`frame-ancestors 'none'`。
- 写请求带非本地 Origin → 403；不提供 CORS；默认只绑 `127.0.0.1`。
- 文件名只作显示，不拼路径；不接收外部 URL。
- 审核者是自述标签，不是认证；不能部署公网多用户。
- 没有后台 worker、真实抽取、Neo4j；这些不因切片通过而完成。

## 8. 目标态整体架构：受控动态 DAG（未实现）

用户已定方向：模型生成动态 DAG，执行前校验，同层有界异步，证据复核，局部重规划，只复用有效只读成功步骤，预算/重复失败/无进展可终止。以下是职责草案，不是已实现模块。

```text
用户/来源 → 规划器（模型生成候选 DAG）
              │
              ▼
        计划校验器（执行前，确定性）
          ├─ 节点参数完整性（必填、类型、范围）
          ├─ 依赖存在且无环（拓扑排序）
          ├─ 工具/权限白名单
          ├─ 预算（节点数、HTTP 次数、时间、token）
          └─ 拒绝：缺参、孤儿依赖、环、超预算
              │
              ▼
        执行器
          ├─ 按层调度；同层信号量限制并发
          ├─ 单节点超时、有限重试、幂等键
          ├─ 只读结果可缓存（严格条件）
          └─ 失败分类：可重试/需重规划/终止
              │
              ▼
        证据复核器
          ├─ 每条结论必须挂 evidence_refs（区域/来源/时间）
          ├─ 规则检查 + 模型复核（模型不能自证）
          └─ 同图 OCR 与 VLM 属相关证据，不当作独立投票
              │
              ├─ 证据不足 → 局部重规划（有界）
              │     └─ 只重跑受影响子图；已成功只读步骤可复用
              ▼
        人工审核（最终批准）→ 发布门禁 → 不可变快照
```

**执行前校验（确定性，不能省）**

| 检查 | 失败处理 |
|---|---|
| 必填参数缺失/类型错 | 拒绝执行，返回字段错误 |
| 依赖指向不存在的节点 | 拒绝执行 |
| 依赖成环 | 拒绝执行（拓扑排序失败） |
| 节点/HTTP/时间/token 超预算 | 拒绝执行或要求缩小计划 |
| 工具不在白名单 | 拒绝该节点 |

**同层并发的边界**：每层最多 N 个并发（可配置），单节点超时；并发只发生在无依赖节点之间；不因为“层内并行”就忽略总预算与下游依赖。

**证据复核的独立性**：同一张图用 OCR 和 VLM 各抽一次，得到的是**相关证据**，不能当两个独立来源投票；复核要看来源、区域、时间与断言是否真的对应。

**局部重规划（有界）**

- 触发：某节点证据不足/失败且可修复；不是所有失败都值得重规划。
- 范围：只重跑受影响子图；上游成功只读结果可复用。
- 上限：重规划次数、总节点数、总 HTTP、总时间都有界。
- 记录：每次重规划的计划版本、原因、被替换节点，供审计。

**只读缓存复用条件（全部满足才可复用）**

1. 原步骤成功且只读；2. 自身参数未变；3. 工具与版本未变；4. 输出 schema 未变；5. 来源内容/版本未变；6. 配置/权限未变；7. 未超过新鲜度窗口。

**不缓存**：人工批准、发布决定、价格/库存等易变事实、任何写操作结果。

**终止条件**

- 预算耗尽（节点/HTTP/时间/token）。
- 重复失败：同一错误指纹连续出现（如两次相同异常）。
- 无进展：连续若干轮没有新增有效证据或推进节点。
- 终止后保留已完成证据、失败分类与计划版本，不伪造成功。

**记忆层（候选，未实现）**：分层记忆——原始执行流水为底账，经验笔记/索引为二次加工，注入上下文只放轻量目录；只沉淀“规则与教训”（如某类版画题名区域常与人物区域重叠），**不缓存作品事实、批准状态或许可结论**；离线整理、可校正、可关闭。

## 9. 关键决策记录

| 决策 | 选择 | 被否方案 | 代价 |
|---|---|---|---|
| 模型输出地位 | 只产生候选，不直接写库 | 模型直接入图 | 需要审核与门禁 |
| 状态建模 | 三状态轴 | 单一 status | UI/调用方要分别理解 |
| 并发控制 | `expected_version` + 写锁 | 仅锁 / 仅版本 | 版本粒度是整个作品，跨断言会冲突 |
| 发布 | 门禁 + 不可变快照 | 直接覆盖当前知识 | 需要快照存储与版本指针 |
| 许可 | 三档策略，`local-*` 禁止发布 | 默认允许 | 必须先确认许可才能发布 |
| 目标态规划 | 模型生成 + 程序预校验 | 边执行边发现 | 需要计划校验器与预算模型 |
