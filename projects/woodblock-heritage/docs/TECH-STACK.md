## 2. 现状：一次审核发布链路用到哪些技术

```text
浏览器（原生 JS + canvas）
  → FastAPI 路由 + Pydantic 校验 + CSP/Origin
  → Pillow 解码 + SHA256 去重（来源登记）
  → service：三状态轴重建、期望版本检查
  → SQLite 事务：幂等键 + 新版本 + review_event + 当前指针
  → 发布门禁：许可 + 全部裁决 + 阻断问题 + 至少一条合格断言
  → 不可变快照 → 当前知识 / 历史
```

- **没有真实 OCR/VLM、没有 Neo4j、没有模型生成 DAG**：这些是目标态或既有资产，不是本切片能力。
- 页面是同源原生实现，CSP 禁止内联脚本；这不是“前端已工程化”。
- 审核者是本地自述标签，不是认证身份。

## 3. 目标态技术栈（用户已定方向：受控动态 DAG + Python + 前端 + 测试）

```text
前端（审核工作台：DAG 视图、证据对照、重规划记录）
  │  REST / 事件
  ▼
Python 服务
  ├─ DAG 规划器（模型生成候选计划）
  ├─ 计划校验器（参数/依赖/环路/预算，执行前）
  ├─ 执行器（同层有界异步、超时、重试上限）
  ├─ 证据复核器（规则 + 模型，人工最终批准）
  ├─ 局部重规划器（只重跑受影响子图）
  ├─ 只读结果缓存（有效、未过期、依赖未变才复用）
  └─ 终止器（预算 / 重复失败 / 无进展）
  ▼
证据与来源存储（SQLite→关系库待定；Neo4j 仅在许可与需求成立后接）
```

**职责边界（关键）**

| 问题 | 归属 | 原因 |
|---|---|---|
| 生成候选 DAG、提出重规划 | 模型（Python 调用） | 需要语义理解；输出是**计划提案** |
| 参数/依赖/环路/预算校验 | 程序（执行前） | 可机械判定，不能等执行到一半才发现 |
| 同层并发上限、超时、重试 | 执行器 | 资源边界必须由代码守 |
| 证据是否支持结论 | 规则 + 模型复核 + 人工 | 模型自评不能替代人工批准 |
| 是否发布 | 人工门禁 + 许可策略 | 许可与责任问题，不能交给模型 |
| 复用旧结果 | 缓存层（严格条件） | 只读、成功、依赖/参数/工具/来源/配置/新鲜度全未变才可复用 |
| 跨会话经验 | 记忆层（候选） | 只沉淀规则/教训，不缓存作品事实与批准状态 |

**尚未选型、不要写死的东西**

- LLM 供应商、模型版本、上下文窗口与费用（未选）。
- 动态 DAG 的规划框架（自研调度器或现成框架，未定）。
- 前端框架（Vue/React/其他，未定；当前原生页面保留）。
- 图数据库（Neo4j 是历史目标；许可、数据量与查询需求未确认前不接）。
- 部署形态与并发容量（未定）。

## 4. 选型理由与代价（现状部分）

| 选择 | 理由 | 代价 / 边界 |
|---|---|---|
| Python + FastAPI | 与抽取/规则生态一致，路由与测试简单 | 单进程；重计算会阻塞，后续需任务化 |
| Pydantic 契约 | 冻结谓词与字段规则可测试 | 谓词扩展要改模型与测试 |
| SQLite + WAL + `BEGIN IMMEDIATE` | 版本、事件、幂等响应同库同事务 | 单写者；多用户/远程弱 |
| Pillow 完整解码 | 防截断/伪造图片，限额明确 | 大图解码耗内存，靠限额兜底 |
| 原生页面 + canvas | 无构建链，坐标覆盖直接可控 | 复杂工作台（DAG/对照）撑不住，需升级 |
| 三状态轴 | 结构/支持/批准分开，坏断言只坏自己 | 调用方要理解三条轴，UI 要分别展示 |
| 许可门禁 | 防误发布，责任边界清楚 | 许可是自述声明，不验证权利人文件 |
