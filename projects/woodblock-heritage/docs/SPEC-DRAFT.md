# 木版年画知识构建：首版规格草案 v0.2

日期：2026-11-06（Asia/Shanghai）。状态：DRAFT / 未批准实现。
这是供另一位 AI 接手讨论的输入包，不是已经通过工具链校验或设计评审的 OpenSpec change。首版与技术建议待确认。

## 1. 产品目标与首版建议

最终目标是支持木版年画的数字化保护、展示和研究探索：以作品为中心组织原图、描述和局部人物/器物等知识，结合领域本体生成可追溯图谱，并支持跨作品检索与有证据的问答。

**建议首版：小批作品的证据化抽取、复核与图谱发布。** 先冻结一个最小本体版本，打通扫描资料→图文配对→候选知识→校验/有限修复→人工复核→小型图谱。
自动本体演化、11 卷全量运行、多模态检索与完整 GraphRAG 在后续阶段分别验证，不以首版未覆盖说明放弃最终目标。

## 2. 用户与关键场景

- **U1 资料整理人员**：导入扫描页/文档，看到作品图、说明的对应关系和待确认配对。
- **U2 编目人员**：查看字段及图像局部证据，修改、驳回或保留未决项，审核后发布。
- **U3 研究者/展示访问者**：按作品、已确认人物/器物关系查找记录，回到原文和图像依据。
- **U4 批任务维护者**：看到失败阶段、调用预算、版本和恢复入口；不要求记住之前对话。

## 4. 功能要求与验收场景

以下要求为首版候选，待评审确认。

### H-01 导入、标识与原始材料

系统应保存文档/图片内容标识、来源、物理页序和可选印刷页码；原始文件与处理产物分开。

- WHEN 相同文件再次导入；THEN 识别重复来源；允许新参数创建新运行，但不把同一来源静默复制成新作品。
- WHEN 文件不能解析；THEN 标记具体文件/页与错误，允许其他独立作品继续，保留重试入口。

### H-02 图文配对

作品候选应关联图像区域、说明区域、页面及配对状态。

- WHEN 一页多图多说明不能唯一配对；THEN 标为待确认，展示候选；不将页面全部文字无条件赋给每幅作品。
- WHEN 图文跨页；THEN 保存多个 Page/Region 的关联，而不是抹掉来源拼成一段。

### H-03 本体约束和知识断言

使用版本固定的最小领域 Schema/词表，输出作品、局部对象、关系、证据和未决项。

- WHEN 图中可确认“人物持长柄器物”，但身份没有可靠依据；THEN 可保留可观察描述，人物名称保持未知或候选。
- WHEN 字段没有依据；THEN 显式留缺失/未决，不根据通识补作者、年代、工艺等事实。
- WHEN 作品存在别名或不同来源记载；THEN 保留来源与差异，规范名不覆盖原文。

宏/中/微分层的具体概念需读取真实本体或由样本讨论确定；不能把项目三层描述成 CIDOC CRM 的原生层次。

### H-04 证据定位与校验

每个要发布的事实应能回到支持它的文本片段或图像区域。

- WHEN 引用区域不存在或不能解析；THEN 校验不通过，不进入正式事实发布。
- WHEN 引用存在但不支持结论；THEN 评测/审核判为证据不支持；存在引用不等于结论正确。
- WHEN Schema、实体引用或关系类型不合法；THEN 记录结构/语义约束错误，与事实错误分开。

### H-05 有限诊断与修复

错误应按文档解析、图文配对、模型抽取、词表归一、本体映射等阶段记录。修复仅使用允许工具并受预算控制。

- WHEN OCR 局部不清；THEN 可提出或执行局部重识别，并保留新旧结果及来源。
- WHEN 同一问题重复修复仍无改善或预算耗尽；THEN 停止并进入 unresolved，不循环到“看起来通过”。
- WHEN 新案例暴露本体表达不足；THEN 保存本体变更建议，不让当前生产批次自行改正式版本。

### H-06 人工复核与发布

界面应展示原页、局部图、原文、候选字段/关系、校验问题和修改记录。

- WHEN 审核人员修改或驳回断言；THEN 保存前后值、审核者、时间和理由，不覆盖历史。
- WHEN 未审核或证据不足；THEN 保留在候选/未决层，不混入首版已确认事实查询。
- WHEN 同一审核版本重复发布；THEN 图谱不会增加重复实体/关系，发布失败可以对账并重试。

### H-07 可恢复任务与可视化查询

系统应记录每件作品的任务状态、阶段产物、模型/提示词/本体版本和消耗，支持页面局部失败及恢复。

- WHEN 服务在抽取后重启；THEN 可以读取已保存产物继续校验/审核，不必整批重新 OCR。
- WHEN 查询作品及人物/器物关系；THEN 返回已审核知识和证据入口，候选和未决信息清晰分区。

## 5. 最小领域与数据契约草案

至少区分作品记录、扫描图像、来源页面与画中局部。确有版本/馆藏实物差异时不能强行合并；是否在首版单独建物理版本实体，根据样本确定。
同一人物概念与“某图中一个人物形象”也应区分：两幅画的局部可描绘同一角色，但不是同一个局部对象。

| 对象 | 最小字段 |
|---|---|
| SourceDocument | document_id, content_hash, filename, source_note, access_policy, imported_at |
| Page | page_id, document_id, physical_index, printed_label?, width, height, render_ref |
| Region | region_id, page_id, kind, bbox, coordinate_system, text?, asset_ref? |
| WorkRecord | work_id, title_claim_refs, source_refs, pairing_status, schema_version |
| DepictedObject | object_id, work_id, category, region_refs, candidate_identity_refs |
| Evidence | evidence_id, region_refs, source_type, quote?, generated_by_stage, source_version |
| Claim | claim_id, subject_id, predicate, object, evidence_refs, support_status, validation_status, review_status |
| Issue | issue_id, work_id, stage, category, affected_refs, status, attempts, resolution? |
| ReviewEvent | event_id, claim_id, before, after, reviewer, timestamp, reason |
| Run/Publication | run_id或publication_id, versions, stage, status, artifacts, budget, idempotency_key |

`Claim.object` 为明确区分的实体引用或字面量，不用一个任意字符串混放实体、时间和说明。
`support_status`：supported / disputed / insufficient；`validation_status`：valid / invalid；`review_status`：unreviewed / approved / rejected。
三个状态分别表达来源支持、结构约束和人工结论；模型判 supported 不等于已由人批准。

坐标建议统一为相对原页的归一化矩形，记录坐标约定及页面尺寸；OCR 像素坐标和图像裁切坐标须显式换算。证据 ID 不能依赖文件临时路径或当前列表顺序。
模型不必输出全部管理字段，由应用分配 ID 和版本；所有输出必须验证引用完整性。

### 断言示例（仅表示数据结构，不是对真实作品的事实判断）

```json
{
  "claim_id": "c-example",
  "subject_id": "figure-example",
  "predicate": "holds",
  "object": {"kind": "entity", "id": "object-example"},
  "evidence_refs": ["ev-example"],
  "support_status": "insufficient",
  "validation_status": "valid",
  "review_status": "unreviewed"
}
```

图谱首版发布只接受满足已确认发布规则的审核版本。争议来源仍保存在记录中，不通过“选一个”删除冲突。

## 6. 流程与 API 草案

```text
上传/登记来源 → 页面解析 → 图文配对 → 受约束抽取
                                      ↓
审核 ← 未决项 / 有限修复 ← 校验与诊断
  ↓
版本化发布 → Neo4j / 作品检索与证据查看
```

| 接口 | 行为 |
|---|---|
| POST /api/v1/heritage/sources | 登记或上传来源，校验文件类型/大小，返回文档标识 |
| POST /api/v1/heritage/runs | 指定来源/页/作品候选及 schema_version，返回 202 和 run_id |
| GET /api/v1/heritage/runs/{run_id} | 返回阶段、逐件结果、未决项与消耗 |
| GET /api/v1/heritage/works/{work_id} | 返回记录、断言、证据入口及审核状态 |
| POST /api/v1/heritage/works/{work_id}/reviews | 带预期版本提交修改/裁决，过期版本返回冲突 |
| POST /api/v1/heritage/publications | 发布指定已审核版本，支持幂等与失败对账 |
| GET /api/v1/heritage/search | 首版按题名/实体/明确关系筛选，不假装已经实现自由问答 |
| GET /health/live 和 /health/ready | 分开报告进程存活与数据库、worker、解析/模型/图谱能力 |

运行阶段建议：ingest / parse / pair / extract / validate / repair / review / publish。
状态建议：queued / running / needs_review / completed / failed / cancelled。批次完成应报告成功、部分、失败和未决件数，不能用一个 completed 隐藏失败作品。

## 7. 推荐技术栈与取舍（待验证）

| 层 | 首版推荐 | 理由与代价 |
|---|---|---|
| 文档解析 | PaddleOCR-VL 适配器，允许导入既有 OCR JSON | 延续历史方向；需核对准确版本、页坐标、资源与字段契约 |
| 视觉/文本抽取 | 一个可配置 VLM/模型服务，结构化输出 | 先建立领域基线；模型通识不自动成为事实证据 |
| 约束 | Pydantic/JSON Schema + 领域规则 + 词表 | 分开结构与事实；只有采用 RDF 时再决定是否需要 SHACL |
| 任务编排 | 先验证持久状态图；LangGraph 为候选 | 适合暂停、修复与人工审核；不能把对话 checkpoint 当全部业务记录 |
| API/审核界面 | FastAPI + Vue 3/TypeScript | 两项目开发习惯接近，但分别独立交付；审核页面是核心功能 |
| 来源/任务/审核存储 | 文件产物目录 + SQLite，记录校验和与版本 | 本地单用户较简单；大规模/多用户时再评估 PostgreSQL/对象存储 |
| 发布图谱 | Neo4j，记录发布版本和断言标识 | 延续旧成果，需实际验证幂等及对账；SQLite 为审核记录权威源，Neo4j 是发布视图 |
| 评测 | pytest、固定集回放、分阶段结果和人工标注 | 软件测试与领域质量评测分别报告 |

新代码不直接照抄论文分章节副本，应在审查后以单一运行入口组织。无需为了本项目先搭通用 Agent 平台或多个数据库集群。

## 8. Harness 边界与版本

记录 document_hash、OCR/VLM 模型版本、提示词版本、本体/词表版本、代码版本、工具尝试、时间和 token/成本。
候选预算：每件作品初始抽取之后最多 2 轮修复；OCR/模型/工具各自设次数及总时限，值根据样本实测再冻结。重试不绕开预算。
修复保留输入、输出与质量变化，不以模型自报置信度作为唯一通过依据；没有新证据时允许停止。
并发发布与审核通过版本校验防止旧结果覆盖新审核。图谱写入失败不撤销审核历史，重试按 publication_id 与 claim_id 对账。

本体只通过独立变更升级。首版 AI 可以提出新类/关系建议，但没有权限直接修改生产 Schema、词表或金标准。

## 9. 测试、评测与验收

**候选小样本计划：** 18 件有图有说明的真实作品，按作品身份及近重复版本分组后，拟分开发/回归/验收各 6 件。最终数量依可用数据与分组调整，需冻结 manifest；它是演示级实验，不支持强统计结论。
没有真实样本时可用合成资料验证接口、状态、坐标与发布流程，但报告必须说明没有验证年画领域效果。

| 层 | 核查内容 |
|---|---|
| 单元 | ID/去重、坐标转换、Schema、实体引用、别名规则、版本匹配 |
| 契约 | OCR/VLM 输出适配，缺字段、格式错、超时和过期结果 |
| 集成 | 任务恢复、独立作品继续、预算停止、审核冲突、图谱幂等与对账 |
| E2E | 导入→证据核对→修改/未决→审核→发布→查询回原图 |
| 领域评测 | 字段及关系 P/R/F1、缺失与多余项、证据支持、未决项质量 |
| 对照 | 固定模型/本体/工具快照和预算上限，对比固定修复与模型选择补证；报告实际消耗 |

**软件验收门槛候选：** 必需用例实际通过；发布事实无悬空证据引用；重复发布不重复建图；未审核与未决结果不混入已确认视图；重启后可恢复；标准前后端构建通过。
**质量门槛待定：** 字段正确率、证据支持率、覆盖与审核耗时目标，在小样本标注、人工裁决规则和用户讨论后确定。结构引用完好不等于证据语义正确，必须另做人工/评测判断。

资料中的“Cypher 命中率 92%”不进入本轮目标或结果，除非找到其原始问题、查询、分母和计算方式。
验收集不反复用于提示词、本体或修复规则调参；一旦转为开发用途，应重新安排独立验收。

| 顺序 | 任务 | 依赖 | 交付证据 |
|---|---|---|---|
| 0 | 样本审阅、领域问题、本体最小版本及验收收敛 | 用户样本与讨论 | 正式规格、样例 JSON、标注约定、设计评审 |

## 11. 运行与交付

首版面向本地可信用户。配置包含模型/OCR渠道、数据库路径、Neo4j 连接、预算及模式，提供无密钥示例，不在日志保存凭据。
服务重启恢复任务和审核记录；原件与数据库须保留可恢复副本，正式发布前以一次导出/恢复演练核对。公网多用户部署另补认证、权限和容量要求。
没有可用 GPU 时先验证受支持的服务调用或既有解析结果导入，不能把 JSON 回放标为 OCR 实时推理。

面试交付包含：真实本体实例、一个来源冲突、一个修复有效或无效的案例、评测分母、实际成本、个人贡献与已知限制。不要只展示图谱节点数量。

## 12. 进入实现前的待决项

P1 用户是否接受小批证据化抽取与审核发布作为首版？
P2 可用样本、旧本体/词表、目标 JSON、来源许可和历史代码范围？
P3 先核对哪些字段/关系，哪些领域问题必须首版回答？
P4 实际 OCR/VLM 渠道、资源和预算；样本与质量阈值？
P5 首版 Neo4j 是必要展示还是第二个小切片？本草案建议纳入审核后的最小发布验证。
这些事项未确认，不把本草案当作完整实现授权。
