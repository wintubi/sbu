## 1. 推荐定位

建议名称：**木版年画多模态知识抽取与质量评测**。如“古版”是资料或论文的正式名称，可保留，但需要明确其实际覆盖年代和对象。

面向编目与知识核验，把扫描图录中的作品图、说明和上下文转成带来源的结构化记录，并支持图谱展示及后续知识探索。重点体现“怎样判断抽取结果可信、怎样定位错误”，而不只展示节点与边。


## 4. 约一分钟介绍稿

> 这个项目面向木版年画的数字化编目和知识核验。原始资料是扫描图录，既有作品图，也有说明文字，所以难点包括 OCR、图文对应，以及同一个人物或题名的不同写法。我采用的整体思路是先解析页面，再用领域本体和受控词表约束图文抽取，经过质量控制后输出规范化数据，用于知识图谱和展示。
>
> 我最关注的是抽出来的信息能否被来源支持，以及发生错误时能否定位到 OCR、配对、模型判断还是本体映射。下一步计划把它改进成可追溯、可恢复的知识处理系统：对证据不足的结果保留未决状态，让补证和修复有预算、有停止条件，并用独立样本验证效果。

该稿描述研究路线与当前改进目标。正式使用前补充真实个人职责、代表作品和已执行实验；不将“下一步计划”改写为已完成成果。

## 5. 面试追问与答题要点

### 为什么不用 OCR 后直接让大模型输出 JSON？

JSON 合法只能说明格式可读。作品和说明可能配错，模型还可能混淆画中人物与真实作者，或补出没有来源的年代、工艺。需要把页面、图像局部和文字证据与知识绑定，并用领域规则检查类型和关系。具体规则带来的提升需要对照实验支撑。

### PaddleOCR-VL 解决什么？小模型一定更快吗？

主要承担文档版面和内容解析，不等于能够可靠解释年画人物身份与文化寓意。速度取决于硬件、页分辨率、裁切策略、批大小及服务开销；参数小是候选优势，不能代替本项目测量。回答时提供历史使用版本、部署方式和实际页耗时，当前这些资料待补。

### 宏观、中观、微观本体具体是什么？

必须拿真实本体中的类、关系和实例说明，不能根据三层名称临时编造。这是项目自身的分层，不是 CIDOC CRM 原生规定。可准备一张表，逐层列出真实概念、适用问题和跨层关系；目前缺资产，暂不定稿具体映射。

### CIDOC CRM 与自己的领域 Schema 有什么区别？

前者提供文化遗产语义建模参考，项目需要按年画编目目标选择复用和扩展。JSON/Pydantic 约束输出结构，图数据库映射负责存储，三者不是同一层。声称“对齐 CRM”应有明确的类/属性映射及扩展说明；仅采用名称不能证明语义一致。

### 同一人物出现在不同作品里怎样建模？

可考虑区分“某幅图中的人物形象实例”和“被描绘的角色/人物概念”：两幅画中的局部不是同一个图像对象，但可能都描绘同一人物。人物、武器或器物身份存在歧义时保留候选与证据。这里是建议模型，旧版本是否如此实现待核对。

### 什么叫事实正确性与编目政策分开？

事实判断检查来源是否支持某项断言；编目政策决定资料如何统一表示。例如原文有两个题名，保留两条来源记载并不冲突于选一个作为展示主标题。别名归一不能抹掉原文差异，也不能把遵守命名规则当成事实已经正确。

### 为什么需要 Agent，固定流程不够吗？

规则和固定流程适合稳定转换与校验。Agent 候选价值在于：根据当前失败原因选择相邻页补证、局部图像重看或实体候选核对。若所有步骤和分支都是事先固定的，应称工作流；只有模型实际选择行动才讨论 Agent 决策。价值通过修复收益、成本及人工复核量对照验证。

### Harness 在这个项目里是什么？

是支持任务持续执行的机制：作品级状态、阶段产物、模型/提示词/本体版本、允许使用的工具、修复预算、停止条件、人工复核与审计记录。当前是改进方向，不能把已有几个脚本直接包装成完整 Harness。

### 怎样判断要停止、补证还是交给人？

建议用可观察条件：关键字段缺证据、来源互相矛盾、约束仍不满足、同一问题反复修复或预算耗尽。允许输出未知和未决项，不能要求每次都填满。模型自报置信度未经校准，不单独作为正确性或停止依据。

### 如何防止本体越改越复杂？

先区分 OCR、配对、抽取、词表与本体问题。只有现有概念确实无法表达领域事实时才考虑改本体。新增项应对应明确查询/编目需求和正反例，并检查对既有数据的影响。本体发布与生产抽取分开，单批结果不能自动改写正式语义。

### 如何评测和避免数据泄漏？

以下为待核对或拟补的设计：按作品身份及近重复版本分组后划分开发、回归、验收集；不能只随机分页面，避免同一作品或说明同时出现在训练提示示例与验收中。视泛化目标再考虑按卷/产地留出。验收样本不反复用于调参，若用于改进，应明确降为开发/回归用途并另设验收集。

### 规则流程与 Agent 怎么公平比较？

固定本体、模型版本、工具能力、输入和预算上限，记录实际消耗。先比较相同抽取基础上，固定修复策略与模型选择行动的区别。预算上限相同并不等于实际成本相同，也不能让一方额外看到人工答案。具体条件和重复运行次数在实验方案中预先约定。

### 如何定位错误与验证修复有效？

保存页面解析、图文配对、原始模型输出、校验报告和规范化结果，找出最早出现偏差的阶段。用单点替换/消融检查主要原因，例如人工校正 OCR 后错误是否消失。上下游错误可能交互，不能只凭最终输出就确定根因。每次修复回归正例和近似反例。

### 知识图谱和普通 RAG 的区别是什么？

文本检索适合找来源描述；图谱适合按明确实体关系跨作品查询；图像检索可补充视觉相似探索。具体采用哪种取决于查询需求。图上存在路径不等于历史因果，视觉相似也不自动证明传承关系。检索问答必须回到证据，图谱规模不等于问答质量。

### Cypher 命中率 92%说明什么？

当前只能说 README 提到该数值，尚未取得计算文件。必须核对是语法执行率、非空结果率还是语义正确率，再提供测试问题、分母、查询和预期答案；未核对前不在面试中当作正确率结论。

## 6. 未来评测口径草案

| 指标 | 定义要点 |
|---|---|
| 字段正确率 | 对应匹配策略和正确性规则下，正确字段数/被评字段数；同时报告覆盖、缺失和多余字段 |
| 实体/关系 P/R/F1 | 先约定别名、局部实例、重复项和边方向的匹配规则，区分严格匹配与归一后匹配 |
| 证据支持率 | 有可定位且能支持相应断言的证据的断言数/输出断言数；“有引用”不等于“被支持” |
| 任务完成率 | 满足预先定义交付要求的作品数/全部任务数；超时和失败不从分母删除 |
| 未决项质量 | 正确发现的真实疑难项、遗漏、误报；不能靠全部留空提高准确率 |
| 修复效果 | 修复前后同一批次质量变化、引入的新错误及额外成本 |
| 人工收益 | 单件审核耗时、需要修改的比例、未决项处理量；记录标注和复核者及裁决规则 |

事实质量金标准需要可追溯标注。专业身份或寓意若无足够证据，不用模型意见直接当金标准。

## 7. 演示脚本建议（尚未实现）

选择一件有清晰作品图与说明的样本：展示扫描页 → 图文配对 → 人物/器物局部 → 结构化字段与来源 → 一条错误的定位与有限修复 → 审核后的图谱关系。
再展示一个证据不足样本，说明系统为何保留未知并交给人；最后展示一个跨作品检索及其原文依据。

以真实标注样例为准，不把假设的作品身份、年代和关联当作事实。演示、回放和实时推理分别标识。
