## 2. 现状：一次 replay 请求用到哪些技术

```text
浏览器（原生 JS，轮询）
  → FastAPI 路由 + Pydantic 校验
  → 规范化 JSON + SHA256 → SQLite 事务（run + 幂等键 + 入口事件）
  → 单线程 worker 取 run → 六阶段状态机
      → ReplayAdapter（fixtures/scenarios.json）
      → domain 纯函数（时间线/约束/质量）
  → 每阶段写 runs.state + events
  → GET 返回 RunView → 页面渲染
```

- **没有 LLM、没有 Java、没有 Vue、没有订单**：这些是目标态，不是当前能力。
- 前端是单文件原生 HTML+JS，无 Node 构建链；这不是“前端已工程化”，只是本地演示页。
- 高德适配器代码在仓库里，但历史 Key 已被回收（`USER_KEY_RECYCLED`/10013），**真实供应商链路未验收**；无 Key 时 LIVE 端点返回 503。

## 3. 目标态技术栈（用户已定方向：Python Agent — Java — Vue）

```text
Vue 前端（聊天 / 店铺 / 订单 / 券）
  │  REST + SSE
  ▼
Java 业务后端（会话、草稿、订单、券、提交权、状态机）
  │  内部 HTTP / 消息（待定）
  ▼
Python Agent 服务（意图解析、工具规划、约束提案、解释）
  │  受治理的工具调用（schema/权限/超时/预算）
  ▼
外部渠道适配器（点评类店铺/报价/券；协议与授权未确认）
```

**职责边界（关键）**

| 问题 | 归属 | 原因 |
|---|---|---|
| 聊天气话、意图解析、方案草案 | Python Agent | 需要模型能力，输出是**提案**不是事实 |
| 金额/距离/营业时间/人数预算的最终判定 | Java 后端（程序核验） | 可复算、可审计，不能让模型自证 |
| 草稿有效期、身份/价格复核、提交权抢占 | Java 后端（单写者） | 需要事务与唯一权威状态 |
| 订单最终状态、券核销 | Java 后端 | 外部结果不确定时按稳定提交标识对账 |
| 页面交互与进度展示 | Vue | SSE 只是通知，重连后以快照为准 |
| 跨会话经验沉淀 | 记忆层（候选） | 只存规则/教训，不缓存价格、库存、营业状态 |

**尚未选型、不要写死的东西**

- LLM 供应商与模型版本（未选；不声称已接 Qwen/OpenAI 等）。
- Agent 框架（LangGraph 等只是候选；当前 replay 切片明确未迁移）。
- Java 框架（Spring Boot 是常见候选，但未建工程）。
- Vue 构建工具与版本（Vite 是常见候选，未建工程）。
- 消息中间件、缓存、部署形态（未定；不虚构 K8s/Redis）。

## 4. 选型理由与代价（现状部分）

| 选择 | 理由 | 代价 / 边界 |
|---|---|---|
| Python + FastAPI | 单进程本地切片，路由/校验/测试一体，启动快 | 不是高并发生产形态；同步 LIVE 路径会阻塞事件循环 |
| Pydantic 契约 | 把“请求是否合法”变成可测试的显式规则 | 模型与业务规则耦合时需拆分，否则契约变胖 |
| SQLite + WAL + `BEGIN IMMEDIATE` | 零运维、整库可备份、事务与幂等好验证 | 单写者；多实例/高并发弱 |
| 自研六阶段状态机 | 阶段可恢复、失败可定位、行为确定 | 不是通用工作流引擎；阶段扩展要改代码 |
| 原生 HTML+JS | 无构建链、证据可直接打开 | 不是工程化前端；复杂交互（聊天/订单）撑不住 |
| 高德适配器 + httpx | 真实渠道的最小接入面，错误可分类 | Key 失效、未联调；预算/deadline 仍是后续 T11 |

## 5. 当前切片明确没引入

- LLM 调用、Agent 框架、MCP、向量库、消息队列、K8s。
- Java 服务、Vue 工程、SSE、订单/支付/券核销。
- 多用户认证、限流、公网部署、生产容量测试。

这些不是“永远不用”，而是**当前切片未做**；目标态见第 3 节。
